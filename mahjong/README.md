# 麻将小游戏

纯前端实现的四人麻将小游戏，玩家坐北位（下方），其余三家由 AI 控制。无需构建，直接打开 `index.html` 即可游玩。

## 牌张

- 万、条、筒各 1~9，每种 4 张。
- 红中 4 张（视为字牌/幺九）。
- 共 112 张。发牌后每人 13 张，庄家 14 张，其余留在牌墙。

## 行牌流程

1. 玩家固定为东、南、西、北四家，人类为北家（`HUMAN = 0`）。
2. 庄家先出牌，之后按东→南→西→北顺时针轮转。
3. 轮到自己时：摸一张牌 → 出牌；若其他玩家打出的牌可被响应，则进入「鸣牌」阶段。
4. 牌墙摸完仍无人胡牌即流局。

## 吃、碰、杠

- **碰**：手中已有两张相同的牌。
- **杠**：手中已有三张相同的牌（明杠）；另有暗杠（自己摸齐四张）与补杠（碰后再摸到第四张）。杠后从牌墙补摸一张。
- **吃**：仅能吃上家打出的牌组成顺子。
- **上听吃**：非上家打出的牌，如果吃进后能通过打出一张进入听牌，也可吃，且吃完后**强制听牌**（自动打出最优听牌张）。这就是「听牌时可以吃三家」。

## 听牌

- 听牌条件：只差一张即可胡牌。
- 进入听牌的方式：
  - 出牌前宣告「听牌」，再打出会进入听牌的那张；
  - 出牌后手牌已成听，可立即宣告；
  - 上听吃后自动强制听牌；
  - AI 打出一张后若已听牌会自动宣告。
- **限制**：
  - 门前清（0 副露）不能听牌；
  - 手把一（4 副露）不能听牌；
  - 听牌后手牌锁定，不能再吃、碰、杠，轮到摸牌后自动打出，直到胡牌或流局；
  - 只能打出后仍能听牌的牌，且不能打出手中唯一的幺九。

## 宝牌

- 有任意一家听牌后翻开宝牌，宝牌取自牌墙末端。
- 若宝牌在牌池与已开门的副露中已见三张，则更换为下一张可用的牌。
- 宝牌仅对已听牌的玩家可见。
- 听牌后摸到宝牌即可视为自摸胡（由玩家决定是否胡）。

## 胡牌条件

- 手牌可拆成「若干顺子 + 至少一个刻子 + 一个对子」。
- 对子为红中时，可以不需要刻子。
- 手中必须有幺九（1、9 或红中）。

## 计分

番数为累加值，每份分数 = `2^番数`：

| 条件 | 番数 |
| --- | --- |
| 黑炮（未听牌者点炮） | +2 |
| 胡牌者为庄家 | +1 |
| 自摸 | +1 |
| 宝牌自摸 | +1 |

支付方式：

- **自摸**：三家各付一份；若付款方为庄家则多付 1 番（×2）。
- **黑炮**（点炮者未听牌）：仅放炮者独付一份；放炮者为庄家时同样多付 1 番。
- **听牌点炮**（点炮者已听牌）：三家各付一份；庄家多付 1 番。

举例：

- 庄家自摸普通牌：番 2，每家 -4，庄家 +12。
- 听牌给庄家点炮：番 1，每家 -2，庄家 +6。
- 听牌给非庄家点炮：番 0，庄家 -2，其他 -1，胡牌者 +4。
- 非听牌给庄家放炮（黑炮）：番 3，放炮者 -8，庄家 +8。

## 庄家与流局

- 庄家胡牌后继续坐庄；其他玩家胡牌则轮到下一家坐庄。
- 流局时庄家不变，且不扣分。
- 庄家回到东家时记为增加一圈。

## 其他

- 胡牌后弹出结算，展示番数明细与各家分数变动。
- 点击「结束游戏」可查看整局统计（圈数、把数、胡牌、流局、各家自摸/点炮/黑炮/宝牌次数与积分），并支持下载战绩图片。
- 页面通过 `sessionStorage` 自动存档，被 Live Server 等自动刷新后可恢复未结束的牌局。

## 项目结构

```
index.html          页面结构
style.css           样式
js/
  app.js            入口：绑定开始/结束按钮，尝试恢复存档
  constants.js      常量（玩家名、花色、人数等）
  tile.js           牌张生成、胡牌判定、听牌、向听数等核心算法
  score.js          番数与分数计算
  game.js           游戏主流程、鸣牌裁决、AI、存档
  ui.js             渲染与交互、结算弹窗、战绩图片导出
svg/                牌面图片
test/
  rules.test.mjs    规则与计分测试
```

## 运行与测试

直接双击打开 `index.html`，或用任意静态服务器（如 VS Code Live Server）运行。

```bash
npm test   # 运行 node test/rules.test.mjs
```
