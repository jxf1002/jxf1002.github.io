# 麻将小游戏

纯前端实现的四人麻将小游戏，玩家坐东位（下方），其余三家由 AI 控制。左=北、上=西、右=南，逆时针行牌。页面是 Next.js 的一个路由，`npm run dev` 后访问 `/mahjong/`。

## 牌张

- 万、条、筒各 1~9，每种 4 张。
- 红中 4 张（视为字牌/幺九）。
- 共 112 张。发牌后每人 13 张，庄家 14 张，牌墙剩 59 张。
- 牌尾预留 **8 张“死墙”**（不参与正常摸牌，专供杠补牌/宝牌）与 **4 张“分章”**（活牌墙摸完后摸），正常摸牌只用到剩余的 **47 张活牌墙**。

## 行牌流程

1. 玩家固定为东、南、西、北四家，人类为东家（`HUMAN = 0`，下方），左=北、上=西、右=南。
2. 庄家先出牌，之后按下→右→上→左逆时针轮转。
3. 轮到自己时：摸一张牌 → 出牌；若其他玩家打出的牌可被响应，则进入「鸣牌」阶段。
4. 活牌墙摸完后进入**分章**：从当前轮到的一家起，四家依次各摸 1 张、不打出，能和则和，四家摸完仍无人和牌即流局。

## 吃、碰、杠

- **碰**：手中已有两张相同的牌。
- **杠**：手中已有三张相同的牌（明杠）；另有暗杠（自己摸齐四张）与补杠（碰后再摸到第四张）。杠后从**牌尾死墙**补摸一张（死墙取完则从活牌墙补）。
- **吃**：仅能吃上家（左家）打出的牌组成顺子。
- **吃上家**：属于正常吃牌。即便吃进后能听牌，也由玩家自行决定是否宣告听牌；但吃进后能听时按「上听」计优先级，优先于碰、杠，不会被别家抢碰。
- **上听吃**：吃另外两家（非上家）打出的牌时，只有当吃进后能通过打出一张进入听牌才允许吃，且吃完后**强制听牌**（自动打出最优听牌张）。这就是「听牌时可以吃三家」。
- 当吃、碰都能进入听牌时，会同时给出「吃·听」与「碰·听」选项，由玩家选择；选择「碰·听」后仍需玩家主动宣告听牌。

## 听牌

- 听牌条件：只差一张即可和牌。
- 进入听牌的方式：
  - 出牌前宣告「听牌」，再打出会进入听牌的那张；
  - 出牌后手牌已成听，可立即宣告；
  - 上听吃后自动强制听牌；
  - AI 打出一张后若已听牌会自动宣告。
- **限制**：
  - 门前清（0 副露）不能听牌；
  - 手把一（4 副露）不能听牌；已有 3 副露时不再允许吃、碰、杠（防手把一）；
  - 断幺九不能听牌：手中（含副露）必须已有幺九（1、9 或红中），靠和到的幺九不算；
  - 清一色不能听牌：万、条、筒至少要有两种，红中不算一种颜色；
  - 听牌后手牌锁定，不能再吃、碰、杠，轮到摸牌后自动打出，直到和牌或流局；
  - 只能打出后仍能听牌的牌（打出后手牌加副露须保留幺九，幺九可在副露里）；
  - 宣告听牌仅限本人回合：出牌前点「听牌」后只能打出听牌张，出牌后成听可立即宣告。

## 宝牌

- 有任意一家听牌后，从**死墙牌尾取走一张**翻开作为宝牌；该物理张不再能被摸到或杠走。杠补牌取的是牌尾的下一张。
- 宝牌按**牌张种类**计：任意一张与宝牌同种的牌被听牌者自摸到时，即视为自摸和，并额外 +1 番。
- 若宝牌在牌池与已开门的副露中已见三张，则再从牌尾取一张换宝（同样取走）。
- 宝牌仅对已听牌的玩家可见。

## 和牌条件

- 手牌可拆成「若干顺子 + 至少一个刻子 + 一个对子」。
- 对子为红中时，可以不需要刻子。
- 手中（含副露）必须有幺九（1、9 或红中）；幺九须在和牌前已在手，靠和到的幺九不算。
- 禁止清一色：万、条、筒至少要有两种，红中不算一种颜色。

## 计分

番数为累加值，每份分数 = `2^番数`：

| 条件 | 番数 |
| --- | --- |
| 黑炮（未听牌者点炮） | +2 |
| 和牌者为庄家 | +1 |
| 自摸 | +1 |
| 宝牌自摸 | +1 |

支付方式：

- **自摸**：三家各付一份；若付款方为庄家则多付 1 番（×2）。
- **黑炮**（点炮者未听牌）：仅放炮者独付一份；放炮者为庄家时同样多付 1 番。
- **听牌点炮**（点炮者已听牌）：三家各付一份；庄家多付 1 番。

举例：

- 庄家自摸普通牌：番 2，每家 -4，庄家 +12。
- 听牌给庄家点炮：番 1，每家 -2，庄家 +6。
- 听牌给非庄家点炮：番 0，庄家 -2，其他 -1，和牌者 +4。
- 非听牌给庄家放炮（黑炮）：番 3，放炮者 -8，庄家 +8。

## 庄家与流局

- 庄家和牌后继续坐庄；其他玩家和牌则轮到下一家坐庄。
- 牌墙摸完并进入分章、四家各摸一张后仍无人和牌，则为流局。
- 流局时庄家不变，且不扣分。
- 庄家回到东家时记为增加一圈。

## 其他

- 和牌后弹出结算，展示番数明细与各家分数变动。
- 点击「回主页面」暂停并回到大厅（自动存档，可继续游戏或开新局）。
- 大厅「查看战绩」可查看整局统计（圈数、把数、总和牌、流局，各家点黑炮/点炮和/黑炮和/自摸和/宝牌和/总和牌次数与积分，其中点炮和+黑炮和+自摸和+宝牌和=总和牌，自摸宝牌仅计宝牌和），并支持下载战绩图片。
- 页面通过 `localStorage` 实时存档，关闭页面后回到大厅可继续未完成的牌局。

## 项目结构

页面是 Next.js 的一个路由（App Router + 静态导出），逻辑与界面分层：

```
app/(tool)/mahjong/page.tsx    路由：metadata + import 游戏样式
components/mahjong/            React 界面层
  MahjongGame.tsx              牌桌、大厅、按钮、听牌交互、引擎事件桥
  tiles.tsx                    牌面与副露渲染
  overlays.tsx                 结算卡、战绩、规则、日志、特效
  tour.ts                      新手指引（driver.js 按需加载）
lib/mahjong/                   纯逻辑层（不碰 DOM）
  constants.ts / tile.ts / score.ts / game.ts / stats.ts / types.ts
public/mahjong/                静态资源：svg/、vendor/（driver.js）
test/mahjong/                  测试
  rules.test.ts                规则与计分（175 条断言）
  ai.test.ts                   AI 单元测试
  ai-sim.ts                    整桌模拟（手动跑，不进 npm test）
  ui.test.tsx                  UI 冒烟测试（jsdom + React）
```

引擎保持命令式：改 `G` 后通过 `setUI({ update, addLog, showModal, showWinBanner, showSummary, effect, actFx })` 喊事件，React 读 `G` 重渲染。

## 运行与测试

```bash
npm run dev     # http://localhost:3000/mahjong/
npm test        # 规则 / AI / UI 测试
npm run verify  # 构建 + 产物自检
```

## 手动测「分章」

分章只在活牌墙摸完时触发，正常对局里很少跑到，可在 `npm run dev` 的浏览器控制台强制进入（无需改代码）：

1. 打开 http://localhost:3000/mahjong/，点「新的游戏」，随便打出一张牌进入正常轮转。
2. F12 打开 Console，输入：
   ```js
   const G = window.__mj.G
   G.deck = []   // 清空活牌墙
   G.wall = 0    // 顶栏显示口径归零
   ```
3. 回到牌桌：轮到你时点一张手牌打出，否则等 AI 出牌。下一家摸牌时活墙已空，立即进入分章——中区显示「分章中」，顶栏由「剩余 0」变为「分章 0/4」，四家依次各摸一张、不出牌，摸完无人和则流局。

> `window.__mj` 只在 `npm run dev` 下注入（导出构建里是死代码），和页面用的是同一份 `G`。

只看「分章中」样式可跳过对局，直接 `document.getElementById('fen-label').classList.add('show')`。

⚠️ `ui('update')` 会写存档，强制改完刷新可能直接进分章。测完点「新的游戏」（会清存档），或执行 `localStorage.removeItem('mahjong_save_v2')`。
